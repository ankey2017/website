- 截图目录：`assets/img/license-keeper/`（8 张，用户口述的 products/license-keeper 目录其实是空的，图在 assets 下）。
  对应关系：login=登录页、shouyue=授权列表首页、xinzcp=新增产品、xinjjhm=新建激活码、bandingsq=绑定机器码生成授权串、miyaogl=密钥管理、daocdr=导入导出、caozrz=操作日志。
- 功能依据真实源码 `E:\vscode\zhouji\license-keeper`（Wails + Go + Vue3 + Element Plus + SQLite）：
  - 登录：bcrypt 加盐、32 位一次性重置密钥、登录态仅在内存（auth_service.go / Login.vue）
  - 授权：激活码 16 位 XXXX-XXXX-XXXX-XXXX；状态 0未激活/1已激活/2已注销/3拉黑；换绑上限 2 次（model.MaxChangeCount）
  - 签发：Ed25519，签名原文模板固定 `product=%s\nlicense_code=%s\nmachine_code=%s\ntype=permanent`（crypto.go），页面上直接展示了这段模板
  - 密钥：私钥 AES-256-GCM 加密存本地 vault.key，不可明文导出；支持加密备份包导入导出
  - 其他：CSV 导出/追加导入（按 license_code 去重）、操作日志 7 类动作只读、保留 3 个月
- 页面结构：Hero → 痛点+4 价值卡 → 8 大功能详解（每节真实截图）→ 六步流程 → 适用/不适用 → 对比表（Excel/第三方授权平台/通用注册机/本软件）→ 试用四步 → 买断 → 8 条 FAQ → 底部 CTA。
- 文案主动交代了这套离线模式的代价（授权串必须人工签发、需要自己在客户端实现验签），避免过度承诺。
