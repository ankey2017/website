功能详解：按一次真实发货的顺序来排

下面都是软件里的真实界面（数据为演示数据）。建产品 → 生成激活码 → 客户付款 → 绑定机器码签发授权串 → 后续注销或拉黑，就是完整的一单。

1. 启动先过本地门禁

软件本身也值得被保护。第一次启动会让你建立管理员账号，密码用 bcrypt 加盐哈希存储，绝不明文入库；同时生成一个一次性展示的 32 位重置密钥，忘记密码时靠它重置。登录态只存在内存里，关掉软件立即失效——别人拷走数据库也进不去。

登录 / 首次初始化：本地校验，无任何网络请求
  • 重置密钥只在初始化成功时显示一次，建议当场存进密码管理器或打印一份，这是唯一的找回入口。
  • 纯本地门禁，不注册账号、不验证邮箱，也不需要"联网激活"。

2. 授权总览：多少码、绑了多少、谁被拉黑

首页就是全部授权记录的台账。顶部五张统计卡实时显示总计、未激活、已激活、已注销、拉黑的数量；下面是可搜索、可筛选的明细表，激活码、机器码、备注、状态、绑定时间、换绑次数一目了然。

授权列表：统计卡片 + 搜索筛选 + 行内操作（绑定授权 / 注销 / 拉黑 / 编辑备注）
  • 三种找法：按激活码、机器码、备注模糊搜索；按状态筛选；按产品筛选。客户一句"我这台机器用不了了"，粘上机器码就能定位到那一条。
  • 备注栏用起来：客户微信、订单号、购买时间都记在这里，将来对账、找人不翻聊天记录。
  • 状态只有四种——未激活、已激活、已注销、拉黑，没有模糊地带，所以永远不会出现"这个码到底还能不能用"的争论。

3. 先把产品登记进来

如果你不只卖一个软件，就在产品管理里挨个登记：产品标识（会写进签名原文，只能用字母、数字、下划线、连字符）、显示名称、备注。登记之后，生成激活码和筛选记录都可以按产品分开，多个产品不会串在一起。

产品管理：一个软件一条记录，标识、名称、备注分开填
改产品标识要想清楚：重命名会按新标识重新签发该产品下所有已绑定激活码的授权串，已经发给客户的旧授权串会立即失效。产品里还有激活码时也不能删除。所以标识建议一次定好，别拿它当"改名"用。

4. 批量生成激活码

选产品、填数量（1~50），点一下生成。每张码都是 16 位、大写字母加数字、四组横杠分隔，重复概率低到可以忽略；生成结果直接列出来，底下一个按钮复制全部，粘到微信、邮件、淘宝发货备注里都行。

新建激活码：选产品、定数量，生成后一键复制全部
  • 先码后人：激活码只是"一张还没兑的票"，客户付款后你把码发过去，他才有资格兑换。码本身不含机器信息，所以可以提前批量备货。
  • 一次最多 50 个，是刻意限制的——批量生成最怕手滑多打两个零，真需要更多就多点几次。

5. 绑定机器码，签发授权串（核心步骤）

客户拿到激活码，在你的软件里点"激活"，软件会显示一串机器码。他把机器码发给你，你在授权列表点【绑定授权】，粘进去、点生成，就能拿到一段 Base64 授权串，发回给客户，他粘贴进软件即完成激活。

绑定授权：填机器码 → 生成授权串 → 一键复制发给客户

签名原文模板是固定的，客户端的验签代码必须一字不差地按同样的顺序拼：

product=qidantong license_code=A1B2-C3D4-E5F6-G7H8 machine_code=客户的机器码 type=permanent

行分隔符为 \n，末尾无换行。界面会把这份原文一起显示出来并支持复制——客户端验签失败时，两边逐字符比对，换行、空格、机器码里的横杠都能立刻看出来。

  • 为什么不怕破解：客户端只内置公钥，只能验签、不能签发。别人拿不到你的私钥，就造不出一段通过验签的授权串。
  • 拉黑状态直接禁止生成，避免你已经决定封掉的码又被自己手滑发出去。
  • 签名原文可复制，是专门为排错做的：客户说"激活不了"，你让他把软件打印的原文发来，一比就知道差在哪。

6. 注销与换绑：客户真的换电脑了

一台电脑用得久了会换，这是正常需求。在列表里点【注销】，原来那条授权串即刻作废，客户可以拿同一张激活码在新机器上重新绑定。

  • 换绑名额是硬的：每次注销占用一次换绑名额，上限 2 次，列表里直接显示"已用/上限"（如 1/2），额度用完按钮就点不动了，只能人工判断放行——这条规则挡的正是"一张码卖十个人"。
  • 拉黑比注销更狠：拉黑后这张码彻底不能再用，也不能再生成授权串；确认是倒卖或破解，拉黑一步到位，事后还能解除。
  • 注销前会先提示剩余次数：不是点一下就完事，确认框里写清楚"本次注销占用一次换绑名额，剩余可换绑次数 N"，手滑也有个缓冲。

7. 日志与备份：出问题时有据可查

授权这事最怕"说不清"。所以每一次关键操作都自动记一条日志：时间、操作者、操作类型、目标、详情、结果；同时提供 CSV 导入导出，让数据随时能带走、能恢复。

操作日志：谁在什么时候做了什么，结果成功还是失败
导入导出：CSV 备份与追加导入，重复码自动跳过
  • 七类操作自动留痕：登录、新建激活码、绑定授权、注销、拉黑、导入导出、密钥备份，可按类型筛选、按关键字搜索。查"上个月是谁把这个码注销了"不用猜。
  • 日志只读，保留最近三个月：不提供编辑和删除入口，避免"记录被改过"这种更麻烦的问题。
  • CSV 是最后一道保险：把全部记录导出成 CSV 就是一份纯文本备份；换机器、重装系统时再追加导入，激活码重复的会自动跳过，并统计出"解析多少条、成功多少条、跳过多少条"。

8. 密钥管理：整个体系里最不能丢的东西

第一次使用要生成一对 Ed25519 密钥。公钥可以随便复制，它要被打包进你卖的软件里用于验签；私钥是命根子，用 AES-256-GCM 加密后存在本地，界面上永远只显示"私钥已加密存储"，看不到明文、复制不了、也导不出明文。

密钥管理：公钥可复制，私钥加密存储，支持加密备份包导入导出
  • 生成密钥对不是"多此一举"：重新生成会让旧密钥立即失效，已发出去的授权串全部验签失败。除非确认要作废历史，别点第二次。
  • 备份包要设密码：导出的密钥备份包本身是加密的，换电脑时导入并输入密码即可恢复。密码丢了，备份包也就废了——密码和备份包建议分开存放。
  • 私钥泄露等于全线失守：谁拿到私钥，谁就能给你的软件无限签授权。所以它不显示明文、不进聊天记录、不进网盘公开链接。
一句话记住分工：公钥跟软件一起发给客户，私钥留在你自己的电脑和加密备份里，两者永远不要放在同一个地方。

常见问题

Q：客户数据、激活码会上传到外网吗？

A：不会。软件不发任何网络请求，全部数据存在本机程序目录下的数据库文件里，连"检查更新"都没有。你的客户名单不会被任何第三方看到。

Q：客户端的验签代码要自己写吗？

A：要。本软件负责生成密钥、签发授权串；你卖的软件里需要内置公钥并实现一次验签（Ed25519 + Base64，按固定模板拼原文）。界面会把签名原文一起显示出来，方便两边对着调。

Q：私钥丢了会怎样？还能恢复吗？

A：私钥加密存在本地。如果磁盘坏了又没有备份包，就无法再签发能通过你旧公钥验签的授权串，只能重新生成密钥对并更新客户端。所以导出密钥备份包并妥善保管这件事，请当成年检一样做。

Q：客户换电脑怎么处理？

A：在授权列表里对该记录点【注销】（占一次换绑名额，每年最多 2 次），然后让客户在新机器上重新给出机器码，你再绑定生成新的授权串即可。次数用完后需人工判断是否放行。

Q：能管几个产品？客户多了会不会卡？

A：产品数量没有硬限制，授权列表支持搜索、状态筛选、按产品筛选和分页（每页 20/50/100 条），几千条记录属于很轻的负载。

Q：数据怎么备份？

A：两条路：一是【导入导出】把全部授权记录导出成 CSV，纯文本、任何工具都能打开；二是直接备份程序目录下的数据库文件。建议定期做一次，成本很低。

Q：换电脑了怎么办？

A：软件激活码绑定本机机器码，换电脑需要重新申请激活码。具体规则和迁移方式请参考统一售后页面。

Q：装不上 / 杀毒软件报毒怎么办？

A：单机小工具可能被部分杀软误报，可先加入信任列表再运行。遇到无法解决的问题，请通过售后页面联系处理。
